## What the competition demonstrates

These are observations from current public repository descriptions, topics and READMEs, not independently verified runtime/quality results. Popularity does not establish which tactic caused adoption. No competitor content or implementation was copied.

| Project / source | Observed positioning, distribution and trust signals | Useful lesson for Glowup |
| --- | --- | --- |
| [Impeccable](https://github.com/pbakaus/impeccable) | A specific “design vocabulary” promise, immediate installer and invocation, pictured comparison, targeted commands, detector/CI documentation, case study and host-specific installation. Topics include agent-skills and design. | Name the job and first action before the catalog. Label our examples' actual provenance; do not borrow its comparison claims or implement another command framework. |
| [Taste Skill](https://github.com/Leonxlnx/taste-skill) | Art direction, imagery and browser review are explained in concrete steps. Standard skills CLI, plugin/clone options, image credits and explicit runtime requirements accompany a visual gallery. Topics cover frontend, UI and agent hosts. | Make evidence inspectable and requirements clear. Existing-app preservation can be Glowup's focus without adding image services or claiming faster execution. |
| [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) | Catalog/design-system generation, searchable resources, CLI/marketplace/manual paths and many stack examples; distinguishes open-source and premium offerings. Broad host/design topics. | Explain our smaller workflow and preservation helpers rather than competing on catalog size. Do not infer its advertised compatibility or speed is independently certified. |
| [Superpowers](https://github.com/obra/superpowers) | A named development workflow, host-specific marketplace instructions, troubleshooting, issues/community channels and contribution rules. Source describes marketplace presence; those listings were not independently executed here. | A clear path from install to real use and support matters. Keep our evidence stages explicit; do not copy its full development methodology or add telemetry. |

All four have active public repositories in the current API snapshot. README visuals and community links are observable; actual community acquisition tactics, recommendation rates, skills.sh rankings and comparative design results were not verified. GitHub stars are interest signals, not users.

**Positioning decision:** focus on redesigning existing web apps with preservation checks. CREATE and REFINE remain visible. This is a product focus, not an exclusive invention: Impeccable also explicitly targets existing interfaces. Glowup must earn trust through reproducible preservation and independent outcomes, not an unsupported uniqueness or superiority claim.
