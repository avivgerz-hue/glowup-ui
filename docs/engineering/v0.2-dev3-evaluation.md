# 0.2.0-dev.3: repeated design evaluation

The candidate is implemented and installable, but it is **not ready for a design-superiority claim or release**. Eighteen actual fresh-context agent implementations completed. The candidate was preferred in nine of twelve blinded model comparisons, with one loss and two ties. Finance did not establish an advantage over the current skill. Independent human review and native-host activation remain unverified.

This is an exploratory in-session evaluation, not a fully controlled native benchmark. [Machine-readable results](v0.2-dev3-results.json) preserve every repeat, functional checks, image hashes and limitations. [Earlier results](v0.2-candidate.md) retain the dev.1/dev.2 losses and ties.

## What was tested

Three repeats for each of two unchanged starting apps, each with no skill, current-main skill and candidate skill: 18 implementations. Finance covers overview, searchable/filterable activity, preferences and transaction dialog. Booking covers home, services, detail, about, contact, reservation steps, validation and confirmation. This does not modify PocketFlow.

- Starting files and task text match within each product; original tracked files were verified against `52be5a00610b355ff44533d1c26e1859fb960360`.
- Candidate skill snapshot: `82b82581020b612e7f65505bc40b762a44667542`, version `0.2.0-dev.3`. Installed payloads were independently hashed. Builders report full entry-point/reference reads before editing, including the relevant study. Explicit file-directed loading is different from native agent activation.
- Each builder received the same requested 18-minute budget and two aesthetic correction rounds. Settings were inherited from the same parent; exact provider model ID and hard budget enforcement were unavailable. Workspaces shared a filesystem isolated by instruction, not a security boundary.
- A common collector checked the served source and actual flows at 1440×900 and 390×844, light theme, reduced motion, en-US, UTC and a fixed clock/data state. Parent did not manually improve any trial app.
- Twelve randomized X/Y assessments used fresh-context **models**, with one mapping across each comparison. Finance reviewers inspected all eight views; booking model reviews cover five critical states at both sizes. All twenty booking views remain available in the human galleries. Human score forms remain empty.

The predeclared directional criterion was candidate preference in at least two of three repeats in **each** product against **both** comparators. It was not met. Even meeting it would be model evidence only, not human validation or proof of universal superiority.

Visible gains included compact financial decision context adjacent to transactions, and booking choices, summaries and continuation controls composed together. The dev.3 study changes address measured dev.2 weaknesses: monthly context below a long phone list, and oversized choice layouts pushing navigation down. Their contribution cannot be separated causally from other instructions or normal model variation in this evaluation.

Tradeoffs remain: some candidate finance headers and introductory panels consume space without improving the task; current skill forms/dialogs can be equally strong or preferable. Booking wins include better task placement, but some service catalog/detail views favor a comparator. These findings do not justify another broad rewrite or selecting only the best output as proof.

## Functionality and objective findings

All 126 original fixture test executions, nine booking builds and 36 desktop/phone flow groups passed. Protected domain/data/routes/tests/package files stayed byte-identical; added application dependencies: zero. The collector captured 252 final views, plus 28 separate matching original-fixture views. No final view had horizontal document overflow or a recorded page error; no unnamed controls were measured. These are narrow checks, not complete preservation or accessibility certification.

Quality warnings were retained. Finance candidate repeat 1 has 30 repeated simple-contrast warning observations versus 8 for current, including secondary text at 4.38–4.40:1. Candidate repeats 2/3 each have 8, mostly breadcrumb separators; context matters. Unavailable booking choices also produce warnings. No trial source was edited by the parent to erase these results. Control finance repeats 1/3 each have a mobile scroll-content occlusion observation, which alone does not prove the action unreachable. Small-target and contrast observations are approximate and repeat shared elements across views; they are not unique defect counts or aesthetic scores.

## Tooling defects found and corrected

- The original booking fixture lacks a `main` landmark. The collector incorrectly waited for `main h1` before capturing it. It now waits for its visible level-one heading and exact confirmation text. Landmark measurement still reports the defect; reservation checks are unchanged. The unchanged original fixture then completed all twenty views and both flows.
- Independent engineering review reproduced `ownedPreview.stop()` returning while a SIGTERM-resistant child still served HTTP. It now terminates only its owned child, escalates after a grace period and requires confirmed closure. A real uncooperative-process regression checks endpoint closure and port release, plus idempotent stop.
- One coordinator capture overlapped a build of the same app and failed during navigation. That failed artifact is preserved; the capture was repeated after the build completed, without app edits. Builds and captures must be sequential per project.
- One 500ms CLI browser fixture assertion failed, then passed in isolation. Scheduling is a hypothesis, not a proven cause. The fixture now uses the helper's supported 3000ms default and retains strict error-count/privacy assertions with sanitized failure detail.
- An optional showcase/chat invocation omitted the configured browser executable and failed before browser work. Separate configured runs used the existing Chromium; no browser permission or network bypass was introduced.

Repository tests: **172 passed** under Node22; canonical validation passed. CREATE/REFINE browser contracts, rendered review/preservation tests, three-app quality checks, studies, Gather, legacy showcase and chat journeys were executed. Check the final PR head's hosted run separately; earlier green commits do not certify later changes.

## Installation and use

The packaged dev.3 candidate and this actual GitHub-source command installed the intended bytes, executed the bundled study helper and removed safely while preserving an unrelated skill:

```powershell
npx.cmd --yes --package=git+https://github.com/avivgerz-hue/glowup-ui.git#d90285cca11bc60fd38eefd33e6ae40c912f0d9e glowup-ui install --scope project
```

Use `npx` on macOS/Linux. Node20+ and Git are required. This immutable engineering snapshot contains the exact evaluated dev.3 canonical skill; later evaluation-only fixes do not change it. It is not a published tag or npm release. Existing different installations are skipped; inspect customizations before choosing replacement. Replace `install` with `uninstall` for safe removal; removing a candidate does not automatically restore a previous customized copy.

Start a fresh host session, explicitly request Glowup, and verify actual complete instruction loading in the host transcript. Installation, matching hashes, builder loading reports and a skill listing do not certify native activation.

## What remains blocked

Provider usage limits paused early cohorts for hours, and command execution permissions changed globally during the interruption. Timestamps are retained privately, but active runtime, calibrated efficiency, token counts and tool-call counts are unavailable. Do not derive speed/cost advantages from wall time.

Native Codex passed the earlier filesystem initialization barrier through the platform-approved execution mechanism with its own read-only sandbox, then stopped before a model turn at proxy HTTP CONNECT403 for `chatgpt.com`. The saved preserving allowlist draft is not applied. The owner must review/publish it in environment settings before a new native preflight. No credentials were copied, login bypassed or network policy evaded.

**Release recommendation: HOLD.** Keep PR #15 a draft. The next evidence needed is native full-instruction activation and a pinned independent retest, plus human judgments of the existing X/Y galleries. Do not merge, tag, release or update published default installation pins based on this report.
