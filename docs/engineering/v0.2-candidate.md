# Glowup UI 0.2.0-dev.1 candidate

This is an implementation candidate, not a published release. Public installation pins remain on v0.1.1. Existing tags are unchanged. No claim of universal compatibility, independent human preference, guaranteed preservation or design superiority follows from this work.

## What changes

The integrated skill already had polish/recompose/reframe, product alternatives, screen coverage, behavioral outcome checks and bounded rendered critique. This candidate preserves those capabilities and adds concrete input to design decisions:

- Two original instructional compositions: a dominant working collection with supporting context, and decision-order selection with an accurate summary. Each uses identical content before/after, structural fragments, phone ordering, screen adaptations and rejection cases. They are hand-authored studies, not agent-generated outcomes.
- Optional problem-based retrieval through `design-brief.mjs --problem hierarchy|selection`; no automatic catalog loading, remote search, new runtime or mandatory planning artifact. The ordinary command remains valid; REFINE/polish returns no study.
- Clear distinction between protected product/brand commitments and incidental starter styling that a broad redesign may replace. Explicit layout, palette or type constraints still win.
- Source validation, installed-byte verification, exact version output and stage-driven terminal progress. No fake delays, telemetry or dependency. Existing conflict/backup/removal semantics remain.

## Reproduce engineering checks

Run `npm test` and `node bin/glowup-ui.mjs validate`. Under Node 22 with the explicitly installed benchmark dependencies/browser, run the existing browser suite and `node benchmarks/studies.mjs`. `--write` deliberately regenerates study captures; the default checks sources, committed capture hashes, retained visible content and document overflow without replacing them. The studies are not aesthetic scores.

The current browser harness uses Playwright's default Chromium launch configuration inside the execution environment. Playwright defaults its Chromium OS sandbox off; do not describe that as an enabled browser sandbox. No host permission, filesystem sandbox or network policy was changed. Browser checks are for trusted local fixtures, not arbitrary untrusted pages.

## Evaluation boundaries

Native Codex 0.163.0 was tried again with `--ephemeral --sandbox read-only`; it failed before a model turn: `failed to initialize in-process app-server client: Read-only file system (os error 30)`. No credentials were copied or permissions weakened. An authenticated outer session does not establish native CLI activation.

The exact-commit six-cell preparation reuses the existing finance and booking fixtures, identical task/app hashes, and independent control/current/candidate workspaces. Fresh-context in-session agent runs are an alternative runner: they cannot certify Claude/Codex/Copilot native loading. Their shared filesystem is an instruction boundary, not a security isolation boundary; exact provider model IDs, token usage and tool counts may be unavailable. Preserve those limitations, ties and losses. Concurrent wall times are not a calibrated speed benchmark.

Final executed results and trial artifacts must be recorded before review. Independent human preference and native-host activation remain release evidence to obtain; do not turn a prepared matrix, a hand-authored study or successful installation into a design win.
